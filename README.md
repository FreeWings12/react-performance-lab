# React Performance Lab

A hands-on frontend engineering project focused on understanding React, TypeScript, Webpack, browser performance, and frontend architecture by building, measuring, and optimizing a realistic application.

## Why this project?

The goal is not to build another demo application or follow a tutorial.

This project is an engineering lab where performance problems are intentionally introduced, measured, investigated, and optimized.

The learning cycle is:

**Build → Measure → Investigate → Hypothesize → Optimize → Measure Again → Understand the Trade-offs**

## What we'll build

An enterprise-style Customer Analytics / Engagement Dashboard with:

* Customer listing and search
* Filtering and pagination
* Customer details
* Campaign information
* Dashboard analytics
* Charts and data visualizations
* API-driven data
* Large datasets and realistic UI workloads

## Performance areas

The project will explore and measure areas such as:

* React rendering and unnecessary re-renders
* Component boundaries and state placement
* Expensive JavaScript work
* Large lists and tables
* API request duplication
* Request cancellation and race conditions
* Network performance
* JavaScript bundle size
* Code splitting and lazy loading
* Webpack optimization
* Image and asset optimization
* Browser rendering performance
* Web Vitals

## Engineering approach

Optimizations will not be made based on assumptions.

For each significant performance problem, the goal is to:

1. Identify the symptom
2. Measure the baseline
3. Investigate the underlying cause
4. Form a hypothesis
5. Make one meaningful change
6. Measure the result
7. Understand the trade-offs
8. Document the findings

Performance numbers will be based on actual measurements from the project rather than assumed or fabricated results.
